Starfall Protocol

A compact endless vertical shooter. Survive a steadily rising stream of enemies and a two-phase boss – while every enemy you miss crashes into Earth.

01

Design

Endless shooters usually punish only the player. Starfall adds a second health bar – Earth – so letting an enemy slip past is a real decision with a cost. Runs stay short so failure feels like an invitation to try again.

Design pillars

P1

Every miss costs

Enemies that get past damage Earth. Losing Earth ends the run.

P2

Constant pressure

No waves or level breaks – the spawn interval shrinks steadily from 1.5 s to 0.4 s over the first three minutes.

P3

Upgrades with weight

Pick 1 of 3 at growing score thresholds. Repair only shows up when you’re actually damaged.

Core loop

  1. Fly & shoot→
  2. Destroy enemies, score→
  3. Threshold: pick 1 of 3 upgrades→
  4. Pressure keeps rising, boss appears↺ repeat
  1. Enemy slips past→
  2. Earth takes damage→
  3. Earth or ship at 0 = game over

Key decisions

Object pooling

Enemies and projectiles are reused instead of instantiated, keeping frame times stable when the screen is full.

ScriptableObjects

Enemy, weapon, boss and upgrade values live in data assets, so balancing happens in the Inspector, not in code.

Interfaces over special cases

IMovementPattern drives the three enemy types, IUpgradeEffect the five upgrades, IDamageable everything that takes hits. A new enemy or upgrade is a new class plus a data asset – the selection and spawning code stays untouched.

Data-driven boss phases

The boss switches to phase 2 at 50% health: fire rate rises from 0.5 to 1.2 shots per second and projectiles get faster. Threshold and values are set in BossData.

Events for feedback

The shield arc listens to PlayerHealth’s OnShieldChanged event instead of polling every frame, keeping game logic and presentation separate.

03

Iteration

What playtesting showed – and what changed because of it.

  1. Iteration 01 · Upgrade strength

    Observed
    In early test runs the upgrades turned out too strong.
    Changed
    Scaled back the fire-rate and speed bonuses in their UpgradeData assets.
    Result
    Upgrades stay noticeable without flattening the difficulty curve.

  2. Iteration 02 · Upgrade pacing

    Observed
    With a fixed score interval, upgrades clustered early in a run and ran dry later.
    Changed
    The gap to the next upgrade now grows after every pick (50 points, then +25 more each time).
    Result
    Upgrade choices spread across the whole run instead of front-loading it.

  3. Iteration 03 · Shield feedback

    Observed
    Picking the shield had no visible effect – and testing showed it gave zero charges, because its value was stored as a fraction and rounded down.
    Changed
    Shield values now count whole charges (minimum one), and a semi-transparent arc sits in front of the ship while a charge is active.
    Result
    The shield works, and players can see at a glance whether they’re protected.
